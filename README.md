
# VPc07 — Restaurant Booking

Учебный проект: система бронирования столов в ресторане.

## Технологии

- Python 3.10+
- PostgreSQL
- psycopg2
- python-dotenv
- tkinter (GUI)

## Возможности

### Пользователи
- Создание пользователя
- Просмотр списка пользователей
- Редактирование имени и телефона
- Удаление пользователя

### Столы
- Создание стола
- Просмотр списка столов
- Изменение номера и количества мест
- Удаление стола

### Бронирования
- Создание бронирования
- Просмотр всех бронирований
- Редактирование бронирования
- Удаление бронирования
- Проверка доступности стола
- Запрет пересекающихся бронирований

## Установка и запуск

### 1. Создать базу данных

В PostgreSQL создать базу:

restaurant_booking

### 2. Создать виртуальное окружение

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

### 3. Установить зависимости

```powershell
python -m pip install -r requirements.txt
```

### 4. Настроить подключение

Скопировать .env.example в .env:

```powershell
Copy-Item .env.example .env
```

Указать реальные параметры PostgreSQL:

```dotenv
DB_HOST=localhost
DB_PORT=5432
DB_NAME=restaurant_booking
DB_USER=postgres
DB_PASSWORD=your_password
```

### 5. Создать таблицы

```powershell
python postgres_driver.py
```

Программа автоматически создаст таблицы:

- users
- restaurant_tables
- bookings

### 6. Запустить приложение

```powershell
python app.py
```

Откроется графический интерфейс Restaurant Booking.

## Проверка доступности

Пример:

Стол №1 забронирован с 19:00 до 21:00.

Попытка бронирования с 20:00 до 22:00
будет отклонена, поскольку интервалы пересекаются.

Бронирование с 21:00 до 23:00
разрешено, поскольку пересечения нет.

При редактировании бронирования программа
исключает текущую запись из проверки конфликтов.

Проверка пересечений выполняется в backend
при создании и изменении бронирований.

## База данных

Используются три связанные таблицы:

- users — пользователи
- restaurant_tables — столы
- bookings — бронирования

При удалении пользователя или стола связанные
бронирования удаляются автоматически
через ON DELETE CASCADE.

## Безопасность

SQL-запросы используют параметризованные значения.
Пароли хранятся в локальном файле .env,
который исключён из Git.
